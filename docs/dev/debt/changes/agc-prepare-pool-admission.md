# libSceAgcDriver

## add the prepare pool's queue depth and content-key pre-check

- [the prepare pool and its admission](../../../core/libs/prx/libSceAgcDriver/Graphics/src/PreparePool.cpp) (libSceAgcDriver) - `PrepareDrawStageA` returned null as soon as `PreparePool::InFlight()` reached `PrepareWorkers()`, so with a draw pipeline of depth 32 a title's builds almost all ran on the committer while the pool held at most `APS5_PREPARE_WORKERS` stage A builds, most of them for draws the resource cache was about to serve. It now admits up to `APS5_PREPARE_QUEUE` (32) in-flight builds and returns null for a draw whose content key `ResourceCache::Holds` already holds, because the commit waits for a pooled build before it looks that key up and then drops the build. It still returns null when the pool is off, the in-flight bound is reached, or the draw has a recipe; a slot's staging flag comes from the draw-staging switches alone, so a slot whose commit turns out not to be recordable is dropped at the consume and the commit builds inline. The caller keeps `state`, `shaders` and the snapshots' backing alive through the consume, and the build runs without `GuestMemory::GpuMutex` on a pool worker, the dispatch counterpart of `PrepareDispatch`. No test covers the admission policy: the gate and `Holds` need a device context and a build, so the effect is measured in a title (`[draws]` `resources` and its `upload` part, `[commit-draw] draw=`, `[draw] pipelined`). A key held at the enqueue but invalidated before the commit, and a draw whose staging flag the commit's own recordability changes, still build on the committer. Closes when: a test drives two draws over one device with the queue bound and the cache pre-check observed.
