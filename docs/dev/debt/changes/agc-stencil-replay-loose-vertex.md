# shader

## add Functional

- [Stencil replay with a loose vertex stage and a capped reference set](../../../core/shader/recompiler/StencilReplay.cpp) (shader recompiler) - `APS5_TRACE_STENCIL_REPLAY` prints why `StencilReplaySafe` refused a program. `APS5_STENCIL_REPLAY_LOOSE_VERTEX` drops the exact-lane part of that analysis for a vertex stage, so a loop header, a lane mask (ballot, lane id, whole-quad mask) and a cross-lane read or write (`readlane`, `writelane`, `readfirstlane` of a non-uniform value, permute, bpermute, swizzle, DPP, half-swap) no longer refuse it. Replay re-executes the vertex stage unchanged with the same vertex data and rewrites only the fragment stage, so a replayed vertex stage needs determinism and freedom from side effects, and LDS, BDA writes, guest memory and image writes, atomics, clocks, undef, `PrimitiveId`, a fault buffer without guarded slots and a `sendmsg` with arguments are still refused. The host does not reproduce the console's wave grouping, so a vertex stage whose output depends on which lanes a wave holds replays with the host's grouping. `APS5_STENCIL_REPLAY_REFERENCES` caps a replay's reference set, sampled evenly over 0-255 with both ends kept, when the stencil export is unbounded: a stencil value outside the sample is never written, so a draw that needs one replays with the wrong stencil.

# libSceAgcDriver

## add Functional

- [Stencil replay of a rect list](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Draw.cpp) (AGC driver) - a rect list (`VGT_PRIMITIVE_TYPE` 7 or 17), whose fragment stage exports the stencil, is replayed like a triangle list: the driver builds it as a patch list of three control points whose generated control and evaluation stages turn each patch into one rectangle, so the replay draws one three-vertex patch per rectangle, once per instance and reference, in the draw's own order. The vertex, control and evaluation stages run per pass as in the draw, and only the fragment stage's export is replaced by a constant reference; the driver-generated control and evaluation stages are neither examined for guest memory writes nor required to be replay-safe. That a three-vertex patch is one rectangle follows from the pipeline the driver builds for a rect list (three control points, quads, four output control points) and is pinned by `agc_driver_rect_list_corner`, `agc_driver_rect_list_indirect` and `agc_driver_rect_list_vertex_layer`; what the console writes for overlapping rectangles with different stencil exports is not measured. The stencil write order within a draw is the guest's, because the replay keeps one rectangle per pass instead of drawing the whole list per reference.
